# Vault data model

[Architecture](ARCHITECTURE.md) · [Model source](../Backend/models/)

MongoDB stores identity, metadata, sharing, integration state, and plan records. File bytes live in object storage. Redis is a separate session/cache layer; it is not the durable source of file contents.

## Core records

| Record | Role | Schema |
| --- | --- | --- |
| User and session | Account identity and active sessions | [userModel.js](../Backend/models/userModel.js), [sessionModel.js](../Backend/models/sessionModel.js) |
| Directory | Parent/ancestor relationships and folder metadata | [directoryModel.js](../Backend/models/directoryModel.js) |
| File | Owner, parent, size, extension, upload state, version, and Git/public-media metadata | [fileModel.js](../Backend/models/fileModel.js) |
| Git workspace and sync job | Repository/branch base, staged state, and integration work | [gitWorkspaceModel.js](../Backend/models/gitWorkspaceModel.js), [gitSyncJobModel.js](../Backend/models/gitSyncJobModel.js) |
| Share link and shared access | Link scopes and sharing relationships | [shareLinkModel.js](../Backend/models/shareLinkModel.js), [sharedAccessModel.js](../Backend/models/sharedAccessModel.js) |
| Plans and subscriptions | Owner configuration, tiers, entitlements, and subscription state | [billingPlanModel.js](../Backend/models/billingPlanModel.js), [subscriptionModel.js](../Backend/models/subscriptionModel.js) |

## File lifecycle

`File.uploadStatus` records `uploading`, `completed`, or `failed`; `uploadId` tracks multipart state. `contentVersion` supports versioned delivery. `parentDir` and ancestor `path` support folder operations; ownership is recorded separately.

The file's `gitStatus` and a workspace's staged list represent local working state. GitHub objects and branch refs are external state. A successful GitHub ref update is not an atomic commit of MongoDB/B2 metadata.

## Sharing and media

File public-access metadata includes enablement, a token, allowed origins, player configuration, and view metadata. Configuration does not prove content confidentiality, unique viewers, or playback success. Public folder manifests are generated by the sharing service; no public tokens or user records belong in examples.

## Consistency boundaries

- MongoDB multi-document transactions require compatible database configuration and apply only to operations participating in that transaction.
- Ancestor arrays simplify traversal and scope checks, but array membership is not an automatic constant-time authorization guarantee.
- Size counters, cached listings, and stored object bytes can diverge after a partial failure; reconciliation and recovery need their own checks.
- Allocated quota is capacity configuration, not a measurement of stored or transferred data.

Read the current schemas and service mutations before writing migrations. This document does not prescribe a destructive migration or guarantee every cross-provider invariant.
